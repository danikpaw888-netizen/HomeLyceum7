# HomeLyceum7 — единая школьная платформа (аналог Ok-Edus / Google Classroom)

Полноценная учебная платформа с ролями (ученик / учитель / родитель / администратор),
входом по email+паролю (JWT), реальной базой данных PostgreSQL и настоящей
загрузкой файлов домашних заданий (как в Classroom).

## Возможности

- **Регистрация и вход**: ученик, учитель и родитель отправляют заявку; доступ выдаётся только после одобрения администратора. Самостоятельная регистрация администратора отключена.
- **Учитель**: создаёт классы, добавляет в них учеников, создаёт домашние
  задания (можно приложить файл-методичку), смотрит сданные работы,
  ставит оценки по 10-балльной шкале и комментарии.
- **Журнал класса** (учитель и администратор): табличный «классический журнал» —
  ученики по строкам, даты по столбцам, клик по клетке ставит оценку (1–10) или
  отметку посещаемости во всплывающем окне. Предметы, которые ведёт учитель,
  подставляются автоматически из расписания; классный руководитель видит и
  редактирует все предметы класса, учитель-предметник — только свои. Есть
  экспорт таблицы в CSV для Excel, средние баллы по ученику и по классу.
- **Оценки по предметам для ученика и родителя**: тот же табличный вид
  (предметы по строкам, даты по столбцам) плюс переключение на вид «по
  предметам» со средним баллом — включает оценки и за домашние задания, и
  за журнал, плюс отметки посещаемости.
- **Расписание**: отдельная вкладка с расписанием по дням недели для каждого
  класса. Заполнять и редактировать может только администратор (предмет,
  учитель, время, кабинет, заметка), остальные роли видят расписание своих
  классов в режиме просмотра.
- **Домашнее обучение**: администратор может перевести ученика на домашнее
  обучение с указанием причины (документ / приказ / заявление) и приложить
  скан документа. При возврате ученика на обычное обучение фиксируются дата
  возврата, весь срок отсутствия и пройденные им темы — вся история хранится
  и видна учителю, администратору, ученику и родителю.
- **Главная страница**: посадочная страница до входа — рассказывает о платформе
  HomeLyceum7 (домашнее обучение для учеников Лицея №7 имени Н.А. Марабаева),
  преимущества, как это работает, кнопки регистрации/входа внизу и в углу.
- **Классы и ученики**: учитель и администратор видят список учеников каждого
  класса и могут легко добавлять их из пула «учеников без класса» — один
  ученик не может состоять в двух классах одновременно, после зачисления он
  пропадает из списка доступных для добавления.
- **Родитель**: видит успеваемость и статус домашнего обучения привязанных
  к нему детей.
- **Администратор**: связывает родителей с их детьми, ведёт расписание и
  записи о домашнем обучении.
- Файлы реально сохраняются на диск backend'а и отдаются по прямой ссылке
  (в проде лучше вынести в S3-совместимое хранилище, но для прототипа
  локального диска достаточно).

## Структура проекта

```
school-platform/
  backend/            # FastAPI + SQLAlchemy + PostgreSQL + JWT
    app/
      main.py          # точка входа
      models.py        # таблицы БД
      schemas.py        # Pydantic-схемы
      auth.py           # JWT, хеширование паролей, проверка ролей
      routers/          # auth, users, classes, assignments, submissions
    uploads/             # сюда сохраняются загруженные файлы
    requirements.txt
    .env.example
  frontend/            # React + Vite + Tailwind + react-router
    src/
      pages/            # Login, Register, StudentDashboard, TeacherDashboard,
                         # ParentDashboard, AdminDashboard
      context/AuthContext.jsx
      api.js            # клиент для запросов к backend
```

## 1. Локальный запуск backend

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# откройте .env и укажите DATABASE_URL от вашей PostgreSQL
# (например, из Neon.tech или Supabase — см. раздел про деплой ниже)
# JWT_SECRET замените на случайную строку

uvicorn app.main:app --reload
```

Backend поднимется на `http://localhost:8000`. Таблицы в базе создаются
автоматически при первом запуске. Документация API (Swagger) доступна на
`http://localhost:8000/docs` — там можно сразу потестировать регистрацию,
создание класса, задания и загрузку файла.

Если пока нет своей PostgreSQL — можно ничего не менять в `.env`: по
умолчанию используется локальный файл `dev.db` (SQLite), чтобы можно было
сразу всё проверить. При первом запуске автоматически создаётся готовый
администратор:

- Email: `admin@homelyceum.local`
- Пароль: `admin12345`
- Роль: `admin`

Создание идемпотентное: при следующих запусках второй такой аккаунт не
создаётся. Эти данные предназначены для локального/тестового запуска; перед
реальным развёртыванием пароль следует изменить, а учётные данные можно
переопределить через `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` и
`BOOTSTRAP_ADMIN_NAME`. Для реальной работы (и деплоя) переключитесь на
PostgreSQL через `DATABASE_URL`.

## 2. Локальный запуск frontend

```bash
cd frontend
npm install
cp .env.example .env     # при необходимости поменяйте VITE_API_URL
npm run dev
```

Откройте `http://localhost:5173`. Зарегистрируйте:
1. Учителя — создаст класс и добавит в него учеников.
2. Ученика (email должен совпадать с тем, что добавляет учитель) — увидит
   задания и сможет сдавать работы.
3. При желании — родителя и администратора, чтобы протестировать привязку
   родитель↔ребёнок и просмотр успеваемости.

## 3. Как пользоваться (сценарий как в Classroom)

1. Учитель входит → создаёт класс "9А" → добавляет туда ученика.
2. Учитель создаёт домашнее задание (предмет, название, описание, дедлайн).
3. Ученик заходит → видит задание в своей ленте → прикрепляет файл (фото,
   документ) и при желании комментарий → жмёт "Отправить решение".
4. Учитель открывает "Проверить работы" под заданием → видит сданный файл →
   ставит оценку от 1 до 10 и комментарий.
5. Ученик видит оценку и комментарий на карточке задания.
6. Если ученика привязали к родителю (через кабинет администратора),
   родитель видит все оценки ребёнка.

## 4. Развёртывание в облаке (бесплатные варианты)

1. **GitHub** — загрузите весь проект в репозиторий.
2. **База данных** — зарегистрируйтесь на [Neon.tech](https://neon.tech) или
   [Supabase](https://supabase.com), создайте PostgreSQL-базу и скопируйте
   `DATABASE_URL` (обычно в формате
   `postgresql://user:password@host/dbname?sslmode=require`).
3. **Backend (Render.com)**:
   - New → Web Service → подключите репозиторий, папка `backend`.
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Environment → добавьте переменные из `.env.example` (`DATABASE_URL`,
     `JWT_SECRET` и т.д.)
   - ⚠️ На бесплатном плане Render диск не постоянный — загруженные файлы
     могут пропасть при перезапуске сервиса. Для прода стоит подключить
     Render Disk (платно) или облачное хранилище (S3/Cloudinary).
4. **Frontend (Vercel.com)**:
   - Import Project → укажите папку `frontend`.
   - Environment Variables → `VITE_API_URL` = адрес вашего backend на Render.
   - Deploy.

## Возможные дальнейшие улучшения

- Вынести хранение файлов в S3-совместимое хранилище вместо локального диска.
- Добавить Alembic-миграции вместо `Base.metadata.create_all`.
- Уведомления (email/push) о новых заданиях и выставленных оценках.
- Групповые чаты/комментарии к заданию.
- Расписание уроков и посещаемость.


### Новая схема доступа

Новые пользователи регистрируются со статусом `pending`. До одобрения администратором вход невозможен. Для нового развёртывания готовый первый администратор создаётся автоматически.
Его можно переопределить через `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD`,
`BOOTSTRAP_ADMIN_NAME` в `.env`. Для существующей базы миграция добавляет поля статуса автоматически и сохраняет текущих пользователей как одобренных.


## Обновления интерфейса

### Расписание
Для каждого урока можно выбрать режим `Каждую неделю`, `Чётная неделя` или `Нечётная неделя`. По умолчанию экран показывает текущую ISO-неделю; переключатель `Обе` показывает полный набор расписания. Номер недели и её чётность рассчитываются по ISO-нумерации недель с понедельником. Старые уроки, созданные до обновления, автоматически считаются еженедельными.

### Журнал
В новых отметках посещаемости используются только три статуса: `Был`, `Отсутствовал`, `Уважительная причина`. Исторические записи со старым статусом «Опоздал» не используются для новых отметок.

### Прикрепление документов при оформлении домашнего обучения

При создании перевода администратор может сразу прикрепить по одному файлу для каждого типа документа: приказ, медицинская справка/заключение, заявление родителя, индивидуальный учебный план, согласие/заявление и другой документ. Поддерживаются PDF, Word, Excel и изображения, до 20 МБ на файл. Документы также можно добавлять позже из карточки уже созданного перевода.

## Домашнее обучение
Причина/основание перевода теперь вводится в одном поле без списка разрозненных вариантов. Документы по-прежнему добавляются отдельно по типам.

## Управление классами (администратор)

В разделе «Классы и ученики» администратор может создать новый класс, изменить его название, добавить ученика в класс и убрать ученика из класса. Класс можно удалить только если у него нет учеников, расписания, заданий, оценок и записей посещаемости — это защищает учебную историю от случайного удаления.

## История классов и безопасное удаление

Удаление класса в админ-панели выполняется как архивирование активной структуры, а не физическое удаление записи из базы. Класс исчезает из активных списков, его ученики автоматически освобождаются для распределения в следующий класс, а оценки, посещаемость, расписание, задания, работы и документы остаются нетронутыми.

Для каждого ученика ведётся отдельная история классов с датами переходов и счётчиками сохранённых оценок и записей посещаемости. При переводе администратора в другой класс старое зачисление закрывается автоматически, новое открывается, а вся учебная история продолжает отображаться в кабинете ученика и родителя.

Существующие базы данных обновляются автоматически при старте backend: создаётся таблица `student_class_history` и добавляются поля архивации класса. Удалять `dev.db` при обновлении нельзя, иначе потеряются имеющиеся данные.
